# Dashboard panels

This page lists every panel of the 3 dashboards and the values that [dashboard data](dashboard-data.md) returns for it. Use it to find the panel and the values that your app needs before you read a dashboard. This page is for developers who call the [Dashboards API](README.md).

The values column gives each key, then its unit in parentheses when it has one. "Rows" means that the panel returns `rows`, and "Series" means that it returns `series`, one for each line, as [What the dashboard data contains](dashboard-data.md#what-the-dashboard-data-contains) describes. The panels are in the order of the dashboard data.

## Live status

Dashboard code: `live_status`. Live status shows the current state of the fleet and has no periods, so a request for its data has no `range`. Its speed panels cover the last 24 hours. To learn what each panel counts, see [Live status](https://app.gitbook.com/s/6RLA9o0EecKpLxHiaeR4/products/dashboards/live-status) in the Location Intelligence documentation.

Notes on the panels:

* **Connection** returns one row for each status: `Online`, `Offline`, `GPS not updated`, and `Other`.
* **Movement distribution** and **Movement** return one row for each state: `Moving`, `Idle`, `Parked`, `Stopped`, and `Unknown`.
* **Fleet details** returns the 50 assets updated most recently, with their latitude and longitude. It reads 1,000 assets at most, and `rowsLeftOut` counts the rest of those 1,000. It returns no address and no geofence, and its `satellites` is always `null`.
* **Asset locations** and **Geofences** aren't in the dashboard data. For the positions of the assets, read **Fleet details**.

Notes on the panels:

* Panels 5, 6, 7, and 12 always have no data: **SOS events**, **Seatbelt events**, **DTC events count**, and **Assets with active fault codes**. Their `unavailable` is the panel's empty message.
* The line charts of the top 10 assets return one series for each asset.
* In the 3 health monitors, `attention` is `critical`, `warning`, or `normal`. **GPS health monitor** also returns `no_fix` for a GPS device without a position.
* The 3 health monitors and **Latest diagnostics** read 1,000 assets at most, and `rowsLeftOut` counts the rest of those 1,000. Their first 50 rows are the ones that need attention most:
  * **GPS health monitor** lists `no_fix` first, then `critical`, `warning`, and `normal`, and within each the highest HDOP first.
  * **Battery power supply health monitor** and **Board power supply health monitor** list the largest drop of `change` first.
  * **Latest diagnostics** lists the latest update first.
* In **GPS health monitor** and **Latest diagnostics**, `satellites` is the fewest satellites that the GPS fix type needs. It isn't a count of the satellites in view. It's `null` when the GPS device reports no fix type.
* **Top 10 events by RPM** returns the 10 hours with the highest RPM in the period, each with its asset. So one asset can appear in several rows.
* **Latest diagnostics** returns `roaming` as `Home`, `Roaming`, or `null`. Its `dtc_codes`, `dtc_events`, `sos`, `seatbelt`, and `max_acceleration` values are always `null`.
