# 2026

## 2026.07 (30 Jul 2026)

Build 2026.07 rebuilds the Navixy Admin Panel and Reports interfaces and adds the Commands functionality. The release also extends IoT Logic, adds Ford Pro integration, includes new GPS devices and fixes.

{% hint style="warning" %}
### Before you update

* **Java:** Standalone build 2026.07 requires Java 25. Make sure your Java version is 25 before running the update script.
* **Backups:** Perform a backup before any Navixy version update. If you are migrating to MySQL 8.4, create and keep separate backups at each major stage: before updating Navixy, before migrating MySQL, and after verifying the completed migration. Contact Navixy support before planning or performing a database migration.
{% endhint %}

### Installation and update

These changes affect how a Standalone instance is installed and updated. For the full procedure, see the [update guide](../overview/how-to-guide/installation/update).

* The updater installs Navixy Admin Panel v3 and updates the related web-server configuration.
* New installations support Ubuntu 26.04 LTS in addition to the previously supported Ubuntu releases.
* The Windows Server installation script now uses MySQL 8.4.10.

### Commands

The new [**Commands**](https://app.gitbook.com/s/446mKak1zDrGv70ahuYZ/guide/devices-and-settings/object-management/commands) block on the device settings page lets you save an instruction once and send it on demand, instead of composing it each time.

Two command types are available. A **device command** sends a protocol-level instruction string directly to the hardware, for example to send a CAN command or activate an output. A **software command** sends an HTTP POST request with a JSON body to an external URL. The request can include current device data such as location, speed, or device ID. Commands are saved per device and dispatched with a single click from the device's Object widget in the Tracking module.

Commands can also be created, updated, listed, and executed through the [Commands API](https://app.gitbook.com/s/6dtcPLayxXVB2qaaiuIL/user-api/backend-api/resources/tracking/tracker/commands). For automated, rule-based sending across several devices, use IoT Logic instead.

### IoT Logic updates

> IoT Logic is a separately licensed feature. These updates apply automatically to Standalone instances that already have it enabled.

[IoT Logic](https://app.gitbook.com/s/446mKak1zDrGv70ahuYZ/guide/account/iot-logic) processes incoming telemetry through configurable flows before it reaches the platform. This release extends it in both directions, an external system can feed data into a flow and a flow can send data out, and adds actions that target devices other than the one that triggered them.

<details>

<summary>What became available in this release</summary>

### Bringing external data in

The **Software** tab in the [Data Source node](https://app.gitbook.com/s/446mKak1zDrGv70ahuYZ/guide/account/iot-logic/nodes/data-source-node) provides an HTTP endpoint that accepts JSON from an external system. Incoming values are matched to devices existing in the Navixy account, then become available alongside the device's own telemetry for the rest of the flow. See [Merging external system data into a flow](https://app.gitbook.com/s/tx3J5BxnWyPV0nP2xr0z/navixy-iot-guide/merging-external-data-into-a-flow).

### Sending data out

The new [Webhook node](https://app.gitbook.com/s/446mKak1zDrGv70ahuYZ/guide/account/iot-logic/nodes/webhook-node) sends a structured HTTP request from a flow using a configurable URL, headers, and JSON body. Allows focused data transmission to external systems instead of complete data forwarding. Can be useful for integrations and alerting.

### Acting on other devices

The [Action node](https://app.gitbook.com/s/446mKak1zDrGv70ahuYZ/guide/account/iot-logic/nodes/action-node) has a new **Advanced** tab that lists additional devices to receive the same commands when the node is triggered. A reading from one device can therefore act on others, for example to switch an output on a second device.

### Other updates

The release also includes the following changes:

* A redesigned start page and flow editor, with a [Flow templates](https://app.gitbook.com/s/446mKak1zDrGv70ahuYZ/guide/account/iot-logic/quick-start-guide/templates) gallery that creates a ready-made flow from a template card. Reduces the entry barrier of flow creation.
* [Geofence functions](https://app.gitbook.com/s/446mKak1zDrGv70ahuYZ/guide/account/iot-logic/nodes/logic-node/geofence-functions) in the Logic node. `inGeofence()`, `enterGeofence()`, and `leaveGeofence()` let flow logic branch on whether a device is inside a geofence, has just entered or left it.
* Support for including a device in several enabled [flows](https://app.gitbook.com/s/446mKak1zDrGv70ahuYZ/guide/account/iot-logic/flow-management) at the same time, so separate processing scenarios no longer have to be combined into one flow.
* [Nodes](https://app.gitbook.com/s/446mKak1zDrGv70ahuYZ/guide/account/iot-logic/nodes) configuration dialog moved from the canvas into a side panel. Now the flow remains wisible while editing a node.
* A [device mapping table](https://app.gitbook.com/s/446mKak1zDrGv70ahuYZ/guide/account/iot-logic/flow-management#mapping-table) in the flow interface that enables quick lookup of device distribution between flows.
* The **Use times** option is removed from the [Initiate Attribute node](https://app.gitbook.com/s/446mKak1zDrGv70ahuYZ/guide/account/iot-logic/nodes/initiate-attribute-node). `genTime()` and `srvTime()` remain available inside formulas, only the automatic introduction of these values is gone. Values previously declared through **Use times** are skipped.
* [Data Stream Analyzer](https://app.gitbook.com/s/446mKak1zDrGv70ahuYZ/guide/account/iot-logic/data-stream-analyzer) indicators showing attributes for commands from Device action or Webhook nodes dispatched during flow processing. The indicator confirms node execution, not delivery to an external destination.
* Removed the visible Default Flow from the flow list. [Default processing](https://app.gitbook.com/s/446mKak1zDrGv70ahuYZ/guide/account/iot-logic/flow-management/default-flow) continues to run automatically for devices that are not included in another flow.
* Flows can be exported and imported as files, so a configuration can be moved between accounts or kept outside the platform.
* Formulas are validated before a flow is saved, and errors are reported in the editor.
* The `device_label` attribute is available in flows, so a device label can be used in conditions and in outgoing payloads.
* BLE data packets are available to flows and distinguishable in Data Strem Analyzer.

### **Iridium SBD**

Iridium Short Burst Data (satellite data transport) lets a device report over the Iridium satellite network where there is no cellular coverage. Navixy can now receive SBD tracking data for supported Teltonika and Galileosky integrations, and supported output-control commands can use the satellite channel when the last connection from the device came in over SBD. Devices on satellite networks are activated manually, as described in [Activate GPS device](https://app.gitbook.com/s/446mKak1zDrGv70ahuYZ/guide/quick-start/activate-gps-device).

<summary>Improved</summary>

* **General Platform improvements**
  * Reimplemented the [Navixy Admin Panel](https://app.gitbook.com/s/KdgeXg71LpaDrwexQYwp/overview), [Reports](https://app.gitbook.com/s/446mKak1zDrGv70ahuYZ/guide/reports), and the device activation wizard on the current Navixy frontend stack. Existing functionality and screen layouts are preserved, so operators do not need to relearn these sections.
  * Hidden and deleted devices no longer count toward an account's device quota.
  * Raised password strength requirements and widened the set of accepted special characters. A new password now must be 12-20 characters long, combine uppercase and lowercase letters, digits, and one special character. It cannot repeat any of the last 10 passwords used on the account. \
    Existing passwords are not affected.
  * Devices can now be found by tag in the device picker, not only by name, which narrows long device lists faster.
  * The service task list is no longer limited to 1,000 entries. Accounts with more tasks can now view, print, and export the full list.
  * Added CSV export of a user's GPS devices to the user details card in the Navixy Admin Panel.
* **Tracking and data**
  * NWS retranslation now identifies devices by their External ID instead of the internal Navixy device ID, so the receiving system can match devices by your own identifier.
  * KML geofence import was reworked and now imports circular geofences, which previously could not be created from a KML file.
  * Added the last connection time to the tracking CSV export.
  * Measurement and aggregation sensor accuracy now accepts decimal values such as 0.25, instead of rounding to whole units.
  * Corrected battery charge readings for devices that report both a percentage and a voltage. When a device sends a percentage and the charge scale of its model is declared in volts, the platform now converts the reported value into that scale instead of showing the two on different scales. Battery level and battery voltage are also handled separately across device protocols now.
  * Improved loading when editing Geo links that contain many GPS devices.
* **Reports and notifications**
  * Geofence and POI names are now hidden in trip report addresses by default. Enable **Include POI in location address** and **Include geofence in location address** in the [report parameters](https://app.gitbook.com/s/446mKak1zDrGv70ahuYZ/guide/reports/specific-report-details/trip-report) to display them.
  * Adopted a new naming convention and format for tachograph DDD files.
  * Converted values in sensor range rule notifications to the account measurement units.
  * Scheduled reports with large device or employee selections now save reliably, where saving could previously fail.
* **Devices and protocols**
  * Added vibration alarm decoding for GT06N devices, so a vibration event can raise a harsh driving alert or an accident report.
  * Added driver identification from an external serial card reader on Suntech devices, so a reader such as the Jmak JM15 can be used to identify drivers.
  * Added hardware mileage input for Jimi VL111.
  * Added engine hour data for Assistant Telematics AVT50.
  * Added ignition reading and immobilizer status and control for Dunasys DCAR S.
  * Added harsh driving support for Gosafe G1C+ and G1C+ 5W.
  * Added humidity and temperature parameters for Megastek MT60Pro.
  * Added reading of ANT battery management system data from electric vehicles.
  * Updated SinoTrack ST906 support after the manufacturer moved from protocol V1 to V8.
  * Corrected the monitoring mode scheme for Concox and Jimi models and their clones.
  * Updated Navtelecom manufacturer and model names to use Latin characters.
  * Split Jimi JC400, JC400D, and JC400P activation profiles for firmware earlier than 1.6.3 and firmware 1.6.3 or newer.
  * Teltonika FMC150 is now activated per hardware variant, FMC150-QJIB0 (2 Digital Outputs) or FMC150-QKIB0 (3 Digital Outputs), instead of one generic profile, so output settings match the device.
